## Описание
Проект направлен на создание вопросно-ответной системы по образовательным материалам.  
Ядро системы — Retrieval-Augmented Generation (RAG): релевантные фрагменты из базы знаний извлекаются и подаются в LLM для генерации точных и воспроизводимых ответов. В ходе работы сравним open-source модели, подходы к разбиению текста и эмбеддингам, добавим ранжирование/переранжирование и изучим варианты улучшений.

## План работ на год
1) **Сбор данных и EDA**  
   - Сбор корпуса по образовательному домену (тексты/документы).  
   - Базовая очистка и нормализация, дедупликация.  
   - Текстовые статистики: размер и распределение документов/фрагментов, частоты/TF-IDF, покрытие терминов, язык/кодировки.  
   - Цель: понять сложность данных и определить стратегию индексирования.

2) **Бейзлайн RAG**  
   - Простой конвейер: индекс → извлечение → генерация.  
   - Open-source LLM диапазона **2-8B** (конкретную модель(и) фиксируем после первых экспериментов).  
   - Первичный набор метрик качества и запуск LLM-разметки для формирования тестового набора.

3) **Улучшение бейзлайна (Retrieve/Indexing)**  
   - Перебор техник чанкования.  
   - Сравнение ≥ 2 эмбеддеров для построения индекса.  
   - Реранжирование кандидатов и настройка top-k/top-p.

4) **Сервис (демо)**  
   - Витрина: **Telegram-бот**.  
   - Логи запросов/ответов, сбор пользовательского фидбека.

5) **Эксперименты с DL**  
   - Сравнение разных архитектур или модернизация RAG (инструменты/агенты).

6) **Доработка по фидбеку**  
   - Улучшения сервиса и качества по результатам обратной связи от команды промышленной разработки.  
   - Шлифовка UX, наблюдаемости и устойчивости.

## EDA
В ходе EDA была обработана выборка из 973 документов: выполнены очистка, нормализация и дедупликация, собраны JSON-отчёт и HTML-дашборд. Ключевые результаты:

- Отлажен технический цикл: тексты очищены, проблемные PDF выделены, уникальность контролируется через хеши SHA-256.
- Частотный анализ и TF-IDF зафиксировали доминирующие термины; разделы «Лексический состав» и «Целевые термины» показывают фактическое распределение словаря.
- Метрики качества показали долю дубликатов, коротких и чрезмерно длинных текстов, а также документы с нестандартными символами и неполной связкой с БД.
- Раздел «Ошибки обработки» собрал файлы, где извлечение провалилось или текст исчез после очистки.
- После подключения Postgres раздел «Сводка классификаций» автоматически заполнится сводными таблицами по типам материалов, уровню образования, целевой аудитории и назначению документов.

## Итоги этапа RAG
- Конфигурация: Chroma коллекция `default_clean` (эмбеддер paraphrase-multilingual-mpnet-base-v2) + bi-rerank `all-MiniLM-L6-v2`, fetch_k=40, top_k=8.
- Поиск (лучшее): recall@5 - 0.0198, recall@10 - 0.0198, MRR - 0.0198, nDCG@3 - 0.0280 (`eval/rerank_results.md`). Базовый embed и cross-encoder реранкеры заметно хуже.
- Ответы (DeepSeek API, 101 вопрос): avg_ref_sim - 0.0886, avg_refs_sim - 0.5998 (`eval/answer_eval_results.jsonl`). Ручной золотой набор 50 вопросов: обе метрики по 0.5327 (`eval/answer_eval_results_gold.jsonl`).
- Локальная модель (Ollama, `qwen2.5:7b-instruct`): 20 вопросов - avg_ref_sim 0.0982 / avg_refs_sim 0.5454, gold 50 - обе 0.5327 (`eval/answer_eval_results_ollama_sample20.jsonl`, `eval/answer_eval_results_gold_ollama.jsonl`).
- Поведение: профильные вопросы про фонд, платформу дают содержательные ответы. small talk - "Недостаточно данных", что корректно при пустом контексте.
- Вывод: связка `default_clean` + `all-MiniLM-L6-v2` остаётся лучшей, узкое место - низкий recall поиска, нужен более сильный эмбеддер, реранкер без полной переиндексации контента.

## FastAPI ML-сервис
- Эндпоинты: `POST /forward` (JSON текст или multipart с `image` и заголовками для доп. полей), `GET /history` (лог запросов), `DELETE /history` (очистка, только админ JWT), `GET /stats` (среднее время, квантиль 50/95/99, длины текстов/токены, размеры изображений; только админ JWT).
- Форматы ответов `/forward`: 400 - bad request (неверный формат), 403 - «модель не смогла обработать данные», 200 - JSON с ответом, для изображений - base64 в поле JSON.
- Логирование: все вызовы пишутся в Postgres таблицу `request_log` (время, статус, модель, длительность, длина текста, токены, размеры изображений, preview ответа).
- Миграции: `alembic upgrade head` (использует настройки БД из env, см. `alembic.ini`). Таблица создаётся миграцией `alembic/versions/0001_create_request_log.py`.
- Запуск сервиса: `uvicorn ml_service.main:app --host 0.0.0.0 --port 8000` (предварительно активировать venv и убедиться, что подняты зависимости и доступна БД, Chroma).
- Авторизация: JWT с секретом `JWT_SECRET` (HS256). Админские методы (`DELETE /history`, `GET /stats`) требуют токен с ролью `admin`.
- Примеры:
  - JSON: `curl -X POST http://localhost:8000/forward -H "Content-Type: application/json" -d "{\"question\": \"Что такое фонд?\"}"`
  - multipart: `curl -X POST http://localhost:8000/forward -F "image=@sample.png" -H "X-Model: demo"`
  - История: `curl http://localhost:8000/history`
  - Статистика: `curl -H "Authorization: Bearer <admin_jwt>" http://localhost:8000/stats`

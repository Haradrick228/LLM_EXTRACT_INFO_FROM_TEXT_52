Как проводили эксперимент

  1. Подготовка корпуса — ~61,543 фрагментов текста экспортированы в JSONL и проиндексированы в **7 отдельных Chroma-коллекциях** (по одной модели эмбеддинга на коллекцию).
  2. Контрольные вопросы — **101** вопросов из `eval/datasets/eval_set_gold_v2.jsonl` — у каждого есть эталонная цитата (`references`) для проверки поиска.
  3. Сравнение всех комбинаций — Для каждой пары «модель поиска × пересортировка» (**7×3=21** вариантов) на каждый вопрос: векторный поиск **40** кандидатов → пересортировка → проверка, попал ли эталон в топ-5, 10 или 20.
  4. Объём прогонов — **2,121** отдельных оценок поиска (101 вопросов × 21 вариантов). Текст ответа нейросети на этом этапе не генерировали — только поиск.
  5. Проверки доверия — Отдельно: SQuAD sanity, neg-control с перетасованными эталонами, лестница A–D, зонд semantic-порога.
  6. Оценка ответов LLM — Для **8** конфигов (FRIDA×3 + строки 3–7 top-8) — отдельный прогон: `RagService.answer` + avg_ref_sim vs `answer_ref`.

Словарь метрик

Recall@k

Доля вопросов (из 101), где хотя бы один из k лучших найденных фрагментов считается «попавшим» по выбранному критерию.

Для каждого вопроса: 1, если hit в топ-k, иначе 0. Итог — среднее по 101 вопросу.

Когда: Главный показатель «нашли ли эталон в выдаче». Смотрим k=5, 10, 20.

Не сравнивать: Нельзя сравнивать recall между разными fetch_k или разными корпусами.

Precision@k

Средняя доля релевантных фрагментов среди k лучших (по тому же критерию hit).

Считается per-query, затем усредняется по 101 вопросу.

Когда: Показывает «засорённость» топа нерелевантными чанками.

MRR (Mean Reciprocal Rank)

Насколько высоко в списке стоит первый правильный фрагмент.

Для вопроса: 1/rank первого hit, или 0 если hit нет. MRR — среднее по 101 вопросу.

Когда: Важно, когда важен порядок: лучше hit на 1-й позиции, чем на 10-й при том же recall.

nDCG@3

Качество ранжирования в топ-3 с учётом позиции релевантного чанка.

Normalized DCG@3 по списку кандидатов после пайплайна.

Когда: Дополнительный сигнал порядка в коротком топе.

Режим substring (дословно)

Чанк «попал», если эталонная фраза из gold — подстрока текста чанка (или наоборот), без учёта регистра.

hit = reference.lower() in chunk.lower() (или обратное включение).

Когда: Жёсткий критерий для отчёта: основная Recall@10 ~6.4% — именно substring.

Не сравнивать: Semantic recall и avg_ref_sim ответа LLM — другие шкалы.

Режим token_f1

Мягче substring: пересечение токенов эталона и чанка (F1 по токенам).

token_overlap_f1_hit между reference и document_text.

Когда: Когда эталон разрезан чанкованием, но часть слов совпадает.

Не сравнивать: Не смешивать с substring % в одной «оценке успеха».

Режим semantic (поиск)

Чанк попал, если косинус эмбеддингов чанка и эталона ≥ порога 0.62 (модель paraphrase-multilingual-mpnet-base-v2).

cosine(embed(chunk), embed(reference)) ≥ 0.62

Когда: Диагностика «по смыслу» на этапе retrieval. Цифры обычно выше substring.

Не сравнивать: 6.4% substring; avg_ref_sim ответа LLM (~64%).

SQuAD: Recall@10 (внешний контроль)

Отдельный «лёгкий» прогон: ~80 вопросов из SQuAD и маленький корпус, где правильный ответ дословно лежит в чанке. Проверяем, что поиск вообще работает.

Тот же substring::recall@10, но на external_sanity, не на 61k корпусе.

Когда: Sanity-check pipeline (порог PASS ≥ 50%; у нас ~82.5%).

Не сравнивать: Цифры полного корпуса 101×61k.

Негативный контроль (перетасованные эталоны)

Те же вопросы, но эталоны перепутаны с другими вопросами. Метрика должна упасть — иначе оценка «рисует» успех.

Честный gold vs shuffled_questions_gold_v2.jsonl, та же ячейка FRIDA+Jina.

Когда: Доверие к pipeline: ~6.4% → ~3.0% при shuffle.

Класс A (лестница метрик)

Эталонный текст не встречается ни в одном из ~61k экспортированных чанков как substring. Поиск по substring принципиально не может «попасть».

metrics_ladder_funnel по trace + corpus JSONL.

Когда: Объясняет потолок ~6% recall — не баг одной модели.

avg_ref_sim (ответ LLM)

Средняя косинусная близость эмбеддингов сгенерированного ответа и поля answer_ref. Это слой «качество ответа», не «нашли чанк».

mean(cosine(embed(answer), embed(answer_ref))) по 101 вопросу.

Когда: Отдельный прогон answer-eval для 8 конфигов (FRIDA×3 + top-8 gap×5; ~0.65 на лучшем).

Не сравнивать: 6.4% substring recall; semantic retrieval hit@k.

Проверки доверия

PASS SQuAD sanity — Recall@10 = 82.5%. ~80 вопросов, ответ дословно в маленьком корпусе. Проверяем, что pipeline живой.

Зачем: если здесь провал — баг индекса/метрик, а не «сложный корпус».

PASS Neg-control — честный 6.4% → перетасованный 3.0%.

Как: `shuffle_eval_questions_neg_control` + тот же retrieval на FRIDA+Jina.

Лестница A–D: ~59% вопросов — класс A (эталон не в корпусе как substring); ~6% — класс D (hit@10). Объясняет потолок recall.

PASS Semantic probe — порог 0.62 согласован с распределением similarity.
